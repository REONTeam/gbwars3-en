# Mobile Adapter LCD/timer transmit service (the project)

the project owns physical Bank `$30:$58E4-$5FF5` (**1,810 retail bytes**, SHA-1 `084cdd6f5039119e4cb278778c41e46c748445a1`). The range begins at the fixed-bank Mobile LCD/timer-service ABI target and ends at the final executable helper before ten zero padding bytes at `$5FF6-$5FFF`; structured Mobile command/template data begins at `$6000`.

`MobileAdapter_DriverLCDStatInterrupt` is the timer-driven counterpart to the project per-byte serial receive service. The fixed-bank wrapper disables/reloads the timer around this call. Inside Bank `$30`, the service advances shared request/packet timers, drives queued transmit bytes, and funnels completion/error states into the packet-state dispatcher. At `$5B25`, `MobileAdapter_TimerStartSerialByteTransfer` reads the next byte through the shared transmit pointer, writes it to `rSB`, advances the pointer, then writes `$03` followed by `$83` to `rSC`, explicitly starting an internal-clock serial transfer.

`MobileAdapter_ProcessCompletedPacketState` at `$5B40` is the major response-state fanout. It normalizes one Transfer Data End response into the existing Transfer Data path and recognizes response-form command values corresponding to Transfer Data, DNS Query, Open/Close TCP Connection, Telephone Status, ISP Login/Logout, Begin Session and adjacent Mobile protocol operations. This supplies receive-side corroboration for the packet-command identities established in the regression suite without changing the separate SDK request-number namespace.

The `$5C1A+` family handles Transfer Data response bookkeeping and chunk copies. `$5D73+` updates connection/response state, while `$5E2E+` maps received command types into shared request/state fields. `$5F05/$5F0A` are common packet-operation setup/start paths; they reuse the already-owned request-channel preparation and state-setter helpers. `$5F65/$5F90` build packet header/checksum state, and `$5F9A` tests transfer completion/status conditions. Names remain contract-oriented where exact public SDK terminology is not independently proven.
